        「Pythonのlist[dict]をC#へそのまま渡したい」という意味なら、通信よりもPythonをC#プロセス内に組み込む方式が候補です。NuGetで最も近いのはPython.NETですが、画像は最終的にC#側の型へ変換する必要があります。

    思考時間: 5s

    あります。今回の目的に最も近いNuGetは Python.NET（pythonnet） です。

    Python.NETを使うと、Pythonを別プロセスとして起動して通信するのではなく、C#プロセス内にCPythonを組み込み、Python関数を直接呼び出せます。Pythonのlistやdict、PIL Image、NumPy配列もPyObjectとして受け取れます。

    ただし重要なのは、

    Pythonのlist[dict]が、自動的にList<Dictionary<string, object>>へ完全変換されるわけではない

    という点です。

    基本的には次のように受け取ります。

    Python list     → PyObject / PyList
    Python dict     → PyObject / PyDict
    numpy.ndarray   → PyObject
    PIL Image       → PyObject

    その後、C#側で各要素を読み出し、画像をbyte[]やBitmapへ変換します。

    1. Python.NETを使った構成

    これまでのHTTP方式は次でした。

    C#プロセス
        ↓ HTTP
    Pythonプロセス

    Python.NETでは次になります。

    C# WinFormsプロセス
        ├─ HALCON
        └─ 組み込まれたPythonランタイム
            ├─ NumPy
            ├─ PIL
            ├─ ONNX Runtime
            └─ Python画像処理関数

    C#からPython関数を直接呼びます。

    C#
    ↓
    module.process_image(...)
    ↓
    Python list[dict]
    ↓
    C#がlistとdictを読み出す

    つまり、HTTPサーバー、ポート、ZIPレスポンスなどは不要です。

    2. NuGetパッケージ

    NuGetでは現在、pythonnetパッケージが提供されています。

    Visual Studioのパッケージマネージャーコンソールなら、例えば次です。

    Install-Package pythonnet

    またはプロジェクトフォルダーで、

    dotnet add package pythonnet

    ただし、Python本体やNumPy、Pillow、ONNX Runtimeまで、すべてNuGetだけで自動的に揃うとは限りません。

    基本的には次が必要です。

    C#側
    - pythonnet NuGet

    PC上
    - 対応するCPython
    - numpy
    - pillow
    - onnxruntime
    - Python担当者のモジュール

    Python自体もアプリへ同梱したい場合はPython.Includedという選択肢もありますが、Python環境とネイティブライブラリの配布管理が増えるため、最初は通常のPython仮想環境を指定する方が分かりやすいです。

    3. Python側の関数例

    Python担当者の出力が次の形式だとします。

    output = [
        {
            "image": image_array,
            "class_name": class_name,
            "score": score
        }
    ]

    例としてimage_processor.pyを作ります。

    import numpy as np
    from PIL import Image


    def process_image(input_image: np.ndarray) -> list[dict]:
        """
        input_image:
            C#から渡されたNumPy配列
            shape = (height, width, 3)
            dtype = uint8

        return:
            加工画像、分類名、スコアを持つdictのlist
        """

        height, width, channels = input_image.shape

        half_width = width // 2
        half_height = height // 2

        regions = [
            input_image[0:half_height, 0:half_width],
            input_image[0:half_height, half_width:width],
            input_image[half_height:height, 0:half_width],
            input_image[half_height:height, half_width:width],
        ]

        output = []

        for index, region in enumerate(regions):
            processed = np.ascontiguousarray(region)

            # 実際にはONNX推論結果を設定する
            class_name = "OK" if index % 2 == 0 else "NG"
            score = 0.95 - index * 0.01

            output.append(
                {
                    "image": processed,
                    "class_name": class_name,
                    "score": float(score),
                    "region_index": index,
                }
            )

        return output

    この場合、画像はPNGへ変換せず、Python内部のnumpy.ndarrayのまま返せます。

    ただしC#側で最終的に表示・保存するには、NumPy配列から画素データを取り出す必要があります。

    4. C#からPythonを初期化する

    以下は概念的な初期化例です。

    using Python.Runtime;

    public sealed class PythonRuntimeManager : IDisposable
    {
        private bool _initialized;

        public void Initialize()
        {
            if (_initialized)
            {
                return;
            }

            string pythonHome =
                @"C:\PythonImageServer\.venv";

            string pythonDll =
                @"C:\Users\User\AppData\Local\Programs\Python\Python311\python311.dll";

            Runtime.PythonDLL = pythonDll;

            PythonEngine.PythonHome = pythonHome;

            PythonEngine.PythonPath = string.Join(
                Path.PathSeparator,
                new[]
                {
                    Path.Combine(pythonHome, "Lib"),
                    Path.Combine(pythonHome, "Lib", "site-packages"),
                    @"C:\PythonImageServer"
                });

            PythonEngine.Initialize();

            /*
            * 別スレッドからPythonを呼び出す可能性がある場合に必要。
            */
            PythonEngine.BeginAllowThreads();

            _initialized = true;
        }

        public void Dispose()
        {
            if (!_initialized)
            {
                return;
            }

            PythonEngine.Shutdown();
            _initialized = false;
        }
    }

    ただし、仮想環境の構成によってPythonHomeやPythonPathの指定方法は変わります。

    特に次を合わせる必要があります。

    C#アプリが64bitならPythonも64bit
    Python.NETが対応するPythonバージョン
    python311.dllなどの場所
    NumPyやONNX Runtimeが入っているsite-packages
    Pythonモジュールの場所
    5. PythonのlistとdictをC#から読む

    Python関数を呼び、戻り値を読む基本例です。

    using Python.Runtime;

    public sealed class PythonClassificationResult
    {
        public required int RegionIndex { get; init; }

        public required string ClassName { get; init; }

        public required double Score { get; init; }

        public required byte[] PixelBytes { get; init; }

        public required int Width { get; init; }

        public required int Height { get; init; }

        public required int Channels { get; init; }
    }

    呼び出し部分です。

    public static List<PythonClassificationResult> CallPython()
    {
        var results = new List<PythonClassificationResult>();

        using (Py.GIL())
        {
            dynamic module = Py.Import("image_processor");

            /*
            * ここでは説明簡略化のため、
            * Python側でテスト画像を作る関数があると仮定。
            */
            using PyObject outputObject =
                module.create_test_results();

            using var outputList = new PyList(outputObject);

            int resultCount = outputList.Length();

            for (int index = 0; index < resultCount; index++)
            {
                using PyObject itemObject = outputList[index];
                using var itemDict = new PyDict(itemObject);

                using PyObject classNameObject =
                    itemDict.GetItem("class_name".ToPython());

                using PyObject scoreObject =
                    itemDict.GetItem("score".ToPython());

                using PyObject regionIndexObject =
                    itemDict.GetItem("region_index".ToPython());

                using PyObject imageObject =
                    itemDict.GetItem("image".ToPython());

                string className =
                    classNameObject.As<string>();

                double score =
                    scoreObject.As<double>();

                int regionIndex =
                    regionIndexObject.As<int>();

                PythonClassificationResult result =
                    ConvertNumpyImage(
                        imageObject,
                        regionIndex,
                        className,
                        score);

                results.Add(result);
            }
        }

        return results;
    }

    実際のPython.NET APIではバージョンによって細かなメソッド名や変換方法に差が出る可能性がありますが、基本構造は、

    Py.GIL()
    ↓
    Py.Import()
    ↓
    Python関数を呼ぶ
    ↓
    PyListとして読む
    ↓
    各要素をPyDictとして読む
    ↓
    dictからimage/class_name/scoreを取得

    です。

    6. NumPy配列をC#で取り出す方法

    Python.NETだけでもNumPyの属性を読み出せます。

    例えばPython側のimageが、

    shape = (480, 640, 3)
    dtype = uint8

    だとします。

    最も理解しやすい方法は、Python側でNumPy配列をbytesへ変換して返す方法です。

    Python側のdictを次のようにします。

    output.append(
        {
            "image_bytes": processed.tobytes(),
            "width": int(processed.shape[1]),
            "height": int(processed.shape[0]),
            "channels": int(processed.shape[2]),
            "dtype": str(processed.dtype),
            "class_name": class_name,
            "score": float(score),
            "region_index": index,
        }
    )

    Python.NETを使っていても、これはPNG変換ではありません。

    NumPy ndarray
    ↓
    非圧縮の画素バイト列
    ↓
    Python bytes
    ↓
    C# byte[]

    画像をPNGへエンコードする処理は不要です。

    C#側では次を取得します。

    using PyObject imageBytesObject =
        itemDict.GetItem("image_bytes".ToPython());

    using PyObject widthObject =
        itemDict.GetItem("width".ToPython());

    using PyObject heightObject =
        itemDict.GetItem("height".ToPython());

    using PyObject channelsObject =
        itemDict.GetItem("channels".ToPython());

    byte[] pixelBytes =
        imageBytesObject.As<byte[]>();

    int width = widthObject.As<int>();
    int height = heightObject.As<int>();
    int channels = channelsObject.As<int>();

    この形が、NumPy配列そのものをC#側から細かく操作するより簡単です。

    7. 推奨するPython内部の戻り値

    Python.NETを採用する場合、担当者には次の形式を提案できます。

    output = [
        {
            "image_bytes": image_array.tobytes(),
            "width": int(image_array.shape[1]),
            "height": int(image_array.shape[0]),
            "channels": int(image_array.shape[2]),
            "dtype": str(image_array.dtype),
            "color_order": "RGB",
            "class_name": class_name,
            "score": float(score),
            "region_index": int(region_index),
        }
    ]

    これはJSONではありません。

    Pythonのlist[dict]のままですが、各値はC#へ変換しやすい型です。

    Python  C#
    list    PyList
    dict    PyDict
    str string
    float   double
    int int
    bytes   byte[]

    これなら、PIL ImageやNumPyオブジェクト自体をC#が深く理解する必要がありません。

    8. NumPy配列をそのままPyObjectで受けることもできる

    もちろん、元の形式を変更せず、

    {
        "image": numpy_array,
        "class_name": class_name,
        "score": score
    }

    でも受け取れます。

    C#側から、

    using PyObject shape = imageObject.GetAttr("shape");
    using PyObject dtype = imageObject.GetAttr("dtype");
    using PyObject bytes = imageObject.InvokeMethod("tobytes");

    のように呼び出せます。

    概念例です。

    using PyObject shapeObject =
        imageObject.GetAttr("shape");

    using PyObject toBytesMethod =
        imageObject.GetAttr("tobytes");

    using PyObject imageBytesObject =
        toBytesMethod.Invoke();

    byte[] pixelBytes =
        imageBytesObject.As<byte[]>();

    ただし、C#側でPythonオブジェクト操作が増えるため、責任分界を考えるとPython側で次まで行う方が簡単です。

    image_array.tobytes()

















    、最終的にはプロセス間や言語間で渡せる形、通常はbyte[]などにする必要があるという点は共通です。

    ただし、PNG/JPEGのバイト列と、NumPy配列をtobytes()した生画素バイト列は別物です。

    PNG/JPEGを渡す場合

    PNGやJPEGは、もともと画像ファイル形式です。

    PNG画像
    ↓
    ファイル内容を読み込む
    ↓
    byte[]

    C#では例えば、

    byte[] pngBytes = File.ReadAllBytes("image.png");

    で取得できます。

    Pythonなら、

    with open("image.png", "rb") as f:
        png_bytes = f.read()

    です。

    このpng_bytesは、PNG形式のヘッダーや画像サイズ、圧縮データなどを含む、PNGファイル全体のバイト列です。

    つまり、

    PNG/JPEGは、そのまま返せないのでNumPy配列に変換する必要がある

    という意味ではありません。

    むしろ逆で、PNG/JPEGファイルは、そのファイル内容をbytesとして読めば、そのまま送れます。

    PNGファイル
    → PNG形式のbytes
    → C#のbyte[]

    NumPy配列に変換する必要はありません。

    NumPy配列をbytesへ変換する場合

    こちらは、

    image_bytes = image_array.tobytes()

    です。

    これはPNGでもJPEGでもありません。

    例えばNumPy配列が、

    shape = (480, 640, 3)
    dtype = np.uint8

    なら、単純に次の画素データだけが並びます。

    R,G,B,R,G,B,R,G,B,...

    C#側では、バイト列だけ受け取っても画像サイズなどが分からないため、別途以下が必要です。

    width = 640
    height = 480
    channels = 3
    dtype = uint8
    color_order = RGB

    したがって、Python側の戻り値は例えば次です。

    {
        "image_bytes": image_array.tobytes(),
        "width": int(image_array.shape[1]),
        "height": int(image_array.shape[0]),
        "channels": int(image_array.shape[2]),
        "dtype": str(image_array.dtype),
        "color_order": "RGB"
    }
    3種類を比較すると
    1. PNG/JPEGバイト列
    NumPy配列
    ↓
    PNG/JPEGとしてエンコード
    ↓
    byte[]

    Python例：

    import io
    from PIL import Image

    buffer = io.BytesIO()
    Image.fromarray(image_array).save(buffer, format="PNG")
    png_bytes = buffer.getvalue()

    特徴：

    画像サイズなどがファイル内部に入っている
    C#でBitmapとして読みやすい
    PNGは可逆
    JPEGは非可逆
    エンコード・デコード時間が必要
    2. 生画素バイト列
    NumPy配列
    ↓
    tobytes()
    ↓
    byte[]

    Python例：

    raw_bytes = image_array.tobytes()

    特徴：

    PNG/JPEGではない
    圧縮されていない
    変換が軽い
    データ量は大きい
    幅、高さ、型などを別途渡す必要がある
    3. Base64文字列
    PNGバイト列または生画素バイト列
    ↓
    Base64変換
    ↓
    文字列

    Python例：

    import base64

    base64_text = base64.b64encode(png_bytes).decode("ascii")

    Base64は画像形式ではありません。

    バイナリ
    → JSONに入れられる文字列

    へ変換するための表現です。

    Base64にするとデータ量が約4/3に増えるので、Python.NETやバイナリ通信なら通常は不要です。

    Python.NETの場合

    Python.NETではPythonのbytesをC#のbyte[]に変換できるため、Base64にする必要はありません。

    次のどちらでも渡せます。

    PNGバイト列を返す

    Python：

    {
        "image_bytes": png_bytes,
        "image_format": "png",
        "class_name": class_name,
        "score": float(score)
    }

    C#：

    byte[] pngBytes = imageBytesObject.As<byte[]>();

    C#ではそのままBitmapへ変換できます。

    using var stream = new MemoryStream(pngBytes);
    using var temporaryBitmap = new Bitmap(stream);
    Bitmap bitmap = new Bitmap(temporaryBitmap);
    生画素バイト列を返す

    Python：

    {
        "image_bytes": image_array.tobytes(),
        "width": int(image_array.shape[1]),
        "height": int(image_array.shape[0]),
        "channels": int(image_array.shape[2]),
        "dtype": "uint8",
        "color_order": "RGB"
    }

    C#では、幅・高さ・チャンネル数を使ってBitmapへ再構築します。

    こちらの方が変換は速くなりやすいですが、実装は少し複雑です。

    今回の理解として正しい表現

    次の理解が正確です。

    PIL ImageやNumPy ndarrayなどの
    Pythonオブジェクトそのものは、
    C#の通常の型として直接扱えない。

    そのため、

    ・PNG/JPEG形式のbytes
    ・生画素のbytes
    ・Base64文字列

    などへ変換して渡す。

    ただしPython.NETでは、NumPy配列自体をPyObjectとして受け取ることはできます。

    numpy.ndarray
    ↓
    Python.NET
    ↓
    PyObject

    その後、C#側から、

    imageObject.InvokeMethod("tobytes");

    のようにPythonのtobytes()を呼ぶことも可能です。

    そのためPython.NETでは、

    必ずPython側でbytesに変換しなければならない

    わけではありません。

    ただ、Python担当者とC#担当者の責任範囲を明確にするなら、Python側でbytesと画像情報に変換して返す方が分かりやすいです。

    まとめ
    PNG/JPEGは、NumPy配列に変換しなくても、そのファイル内容をbytesとして送れます。
    NumPyのtobytes()は、PNG/JPEGではなく非圧縮の生画素データです。
    Base64は、バイト列を文字列へ変換する方法です。
    Python.NETならBase64は通常不要です。
    表示の簡単さ重視ならPNGバイト列。
    速度重視なら生画素バイト列が候補です。
