    Visual C++ Runtime x64 オフライン 更新手順書¶

    1. 目的¶

    WindowsのオフラインPCで使用している Microsoft Visual C++ Runtime を、オンラインPCで取得した公式インストーラを用いて更新する。

    今回の主目的は、ONNX Runtime実行時に発生している以下のエラーについて、Visual C++ Runtimeが原因か切り分けることである。

    1
2
    ImportError: DLL load failed while importing onnxruntime_pybind11_state:
A dynamic link library (DLL) initialization routine failed.

    イベントビューアーでは、旧問題環境で以下が確認されている。

    1
2
3
4
5
    障害モジュール:
MSVCP140.dll

例外コード:
0xc0000005

    2. 重要事項¶

    Visual C++ RuntimeはPythonのvenvとは異なり、Windows全体にインストールされるシステム側コンポーネントである。

    そのため、

    1
    C:\ort_test

    の中だけで更新を完結させることはできない。

    既存環境への影響を最小限にするため、

    1. 更新前のバージョンを記録する
    2. 既存Runtimeをアンインストールしない
    3. Microsoft公式の最新版x64をそのまま上書き更新する
    4. 更新後に再起動する
    5. ONNX Runtimeの挙動を比較する

    という手順で実施する。

    Microsoftによると、Visual Studio 2017以降のMSVC v14系は共通のVisual C++ v14 Redistributableを使用し、最新v14 Runtimeへの更新が推奨されている。

    3. 使用するパッケージ¶

    今回使用するのは、

    1
2
    Visual C++ v14 Redistributable
X64版

    である。

    ONNX Runtime CPU版およびPython 3.11 x64を使用しているため、今回の切り分けでは x64版を使用する。

    Microsoft公式の最新版ページでは、x64版として

    1
    vc_redist.x64.exe

    が提供されている。Microsoftは、アプリの対象アーキテクチャとRedistributableのアーキテクチャを合わせるよう案内している。

    既存PCにx86版Visual C++ Runtimeが入っていても、今回の作業では削除しない。

    また、Visual C++ 2013以前のRedistributableも削除しない。これらはv14系とは別にside-by-sideで保持される。

    4. オンラインPC：インストーラ取得¶

    4.1 Microsoft公式ページを開く¶

    Microsoft Learnの

    1
    Microsoft Visual C++ Redistributable latest supported downloads

    ページを開く。

    ページ内の

    1
    Visual C++ v14 Redistributable

    →

    1
    Latest supported redistributable version

    を確認する。

    Architecture一覧から

    1
    X64

    を選択してダウンロードする。

    ファイル名：

    1
    vc_redist.x64.exe

    Microsoft公式では、このX64リンクは最新版へ向く固定リンクとして提供されている。

    5. オンラインPC：取得したファイルを保存¶

    今回の検証用フォルダを使用する場合は、

    1
    C:\ort_test\installers

    へ保存する。

    例：

    1
2
3
    C:\ort_test
└─ installers
   └─ vc_redist.x64.exe

    6. オンラインPC：インストーラの署名確認¶

    オフラインPCへ持ち込む前に、Microsoft署名の正規ファイルであることを確認する。

    PowerShellで実行する。

    1
    Get-AuthenticodeSignature C:\ort_test\installers\vc_redist.x64.exe

    確認する項目：

    1
    Status

    が

    1
    Valid

    であること。

    さらに署名者にMicrosoftが表示されていることを確認する。

    Microsoftも、Visual C++ RedistributableはMicrosoftサイトから取得し、Microsoft署名済みのものだけを使用するよう案内している。

    7. オンラインPC：インストーラ自体のバージョン確認¶

    PowerShellで確認する。

    1
    (Get-Item "C:\ort_test\installers\vc_redist.x64.exe").VersionInfo.FileVersion

    この値を記録しておく。

    例：

    1
    14.xx.xxxxx.x

    Microsoftは最新版のバージョン番号を固定掲載しておらず、最新版インストーラのファイルプロパティから確認する方法を案内している。

    8. オフラインPCへコピー¶

    1
    vc_redist.x64.exe

    をオフラインPCへコピーする。

    コピー先例：

    1
    C:\ort_test\installers\vc_redist.x64.exe

    9. オフラインPC：更新前の状態を記録¶

    更新前に必ず現在のRuntimeバージョンを記録する。

    PowerShellで以下を実行する。

    1
    (Get-Item "C:\Windows\System32\MSVCP140.dll").VersionInfo.FileVersion

    1
    (Get-Item "C:\Windows\System32\VCRUNTIME140.dll").VersionInfo.FileVersion

    1
    (Get-Item "C:\Windows\System32\VCRUNTIME140_1.dll").VersionInfo.FileVersion

    正常動作した時の値

    1
    14.38.33135.0

    この差は今回の原因切り分け上重要なので、更新前の値を必ず残す。

    10. ONNX Runtimeの更新前テスト¶

    Visual C++ Runtimeを変更する前に、検証用venvで現在の挙動を確認する。

    例：

    1
    C:\ort_test\venv\Scripts\python.exe -c "import onnxruntime as ort; print(ort.__version__)"

    正常なら、

    1
    1.28.0

    と表示される。

    問題PCで、

    1
    DLL load failed while importing onnxruntime_pybind11_state

    が発生することを再確認する。

    この結果を

    1
    VC++ Runtime更新前：NG

    として記録する。

    11. 実行中アプリケーションを終了¶

    Visual C++ RuntimeのDLLを使用しているアプリケーションが起動していると更新に失敗する場合がある。

    更新前に可能な限り以下を終了する。

    1
2
3
4
5
    Python
Visual Studio
VS Code
対象アプリケーション
その他開発ツール

    Microsoftも、ファイルが使用中の場合はインストール失敗の原因になり得るとして、実行中ソフトを閉じるよう案内している。

    12. Visual C++ Runtimeを更新¶

    方法A：GUIで更新する¶

    今回はこちらを推奨する。

    1
    C:\ort_test\installers\vc_redist.x64.exe

    を右クリックし、

    1
    管理者として実行

    を選択する。

    MicrosoftもVC Redistインストール時には管理者実行を推奨している。

    既存のVisual C++ v14 Runtimeが古い場合、通常は新しいRuntimeへの更新として処理される。

    画面の指示に従ってインストールする。

    13. コマンドラインで更新する場合¶

    GUIを使用しない場合は、管理者PowerShellから以下でも実行できる。

    1
    C:\ort_test\installers\vc_redist.x64.exe /install /passive /norestart

    意味：

    1
2
3
4
5
6
7
8
    /install
    インストール

/passive
    進行状況だけ表示

/norestart
    自動再起動を抑止

    Visual C++ Redistributableは /install、/repair、/uninstall、/passive、/quiet、/norestart、/log などのコマンドラインオプションを公式にサポートしている。

    ログを明示的に残す場合は、

    1
    C:\ort_test\installers\vc_redist.x64.exe /install /passive /norestart /log C:\ort_test\vc_redist_install.log

    とする。

    今回の原因調査ではログを残しておくと後で比較しやすい。

    14. 「Repair」が表示された場合¶

    インストーラ起動時に、

    1
2
3
    Repair
Uninstall
Close

    等が表示される場合がある。

    この場合、まずインストーラ自体のバージョンと現在インストール済みRuntimeのバージョンを確認する。

    すでに同じ最新版が入っている場合は、

    1
    Repair

    を実行してRuntimeファイルを修復する。

    ただし、今回の目的が

    1
    14.34 → 最新版

    への更新であれば、古いRuntimeを先にアンインストールする必要はない。

    15. PCを再起動¶

    インストール完了後は、Windowsを再起動する。

    1
2
3
    スタート
→ 電源
→ 再起動

    MicrosoftもVisual C++ Redistributableを個別インストールした場合、再起動を求められることがあるとしている。

    今回のDLL初期化問題では、古いDLLがプロセスにロードされたままになることを避けるため、再起動は実施する。

    16. 更新後のRuntimeバージョン確認¶

    再起動後、PowerShellを開き以下を実行する。

    1
    (Get-Item "C:\Windows\System32\MSVCP140.dll").VersionInfo.FileVersion

    1
    (Get-Item "C:\Windows\System32\VCRUNTIME140.dll").VersionInfo.FileVersion

    1
    (Get-Item "C:\Windows\System32\VCRUNTIME140_1.dll").VersionInfo.FileVersion

    更新前：

    1
    14.34.31938.0

    更新後：

    1
    14.xx.xxxxx.x

    のように、新しい値へ変更されていることを確認する。

    3つが同じ系列のバージョンになっていることも確認する。

    17. ONNX Runtime再テスト¶

    Visual C++ Runtime更新以外は変更せず、更新前と同じvenvで再度実行する。

    1
    C:\ort_test\venv\Scripts\python.exe -c "import onnxruntime as ort; print(ort.__version__)"

    結果を記録する。

    パターンA¶

    1
2
3
4
5
    更新前：
DLL load failed

更新後：
1.28.0

    この場合、

    1
    Visual C++ Runtime環境が原因だった可能性が非常に高い

    と判断できる。

    パターンB¶

    1
2
3
4
5
    更新前：
DLL load failed

更新後：
DLL load failed

    この場合、

    1
    Visual C++ Runtimeのバージョンだけが原因ではない

    と判断する。

    requirementsの違い、他のネイティブDLL、Windows環境差などを引き続き調査する。

    18. イベントビューアーも再確認する¶

    まだエラーになる場合は、

    1
2
3
    イベントビューアー
→ Windowsログ
→ アプリケーション

    を確認する。

    特に、

    1
2
    障害モジュール
例外コード

    を見る。

    更新前と同じ、

    1
2
    MSVCP140.dll
0xc0000005

    なのか確認する。

    19. インストール自体が失敗した場合¶

    Visual C++ Runtimeのインストールに失敗した場合は、まず以下を確認する。

    1
2
3
    管理者として実行したか
実行中アプリを終了したか
Windows再起動後に再試行したか

    Microsoftは、VC Redistインストール失敗時の代表的な原因として、

    1
2
3
4
5
    権限不足
ファイル使用中
セキュリティソフト
古いWindowsコンポーネント
Windows Installerキャッシュ破損

    などを挙げている。

    20. インストールログ¶

    VC Redistは通常、

    1
    %TEMP%

    配下へログを作成する。

    ログ名例：

    1
    dd_vcredist_x64_YYYYMMDDHHMMSS...

    Microsoftも、VC Redistの診断時にはこのログを確認するよう案内している。

    今回の手順で明示ログを指定した場合は、

    1
    C:\ort_test\vc_redist_install.log

    を確認する。

    21. 既存Runtimeを先に削除しない¶

    今回の切り分けでは、

    1
2
3
4
5
    古いVC++ Runtime
↓
アンインストール
↓
最新版を新規インストール

    とはしない。

    まず、

    1
2
3
    古いVC++ Runtime
↓
最新版をそのまま上書き

    とする。

    これにより、既存アプリケーションへの影響を最小限にしつつ比較できる。

    Microsoftもv14系について、最新v14 Runtimeへのin-place upgradeを案内している。

    22. x86版について¶

    今回のONNX Runtimeは、

    1
    onnxruntime-1.28.0-cp311-cp311-win_amd64.whl

    なのでx64アプリケーションである。

    そのため今回更新対象は、

    1
    vc_redist.x64.exe

    とする。

    既存の

    1
    Microsoft Visual C++ Redistributable (x86)

    は削除しない。

    32bitアプリケーションが使用している可能性があるためである。

    23. 今回の推奨検証順¶

    1
2
3
4
5
6
7
8
    ① VC++ Runtime 14.34のまま
       ↓
② 新しい C:\ort_test\venv を作成
       ↓
③ 今回成功した5個のwheelから
   onnxruntime 1.28.0をインストール
       ↓
④ import確認

    ここでエラーが再現したら、

    1
2
3
4
5
6
    ⑤ 他の環境は一切変更せず
   VC++ Runtime x64だけ最新版へ更新
       ↓
⑥ Windows再起動
       ↓
⑦ 同じvenvで再度import

    とする。

    この方法なら、

    1
2
    VC++ Runtime更新前 → NG
VC++ Runtime更新後 → OK

    という比較ができ、原因の切り分けとして非常に強い結果になる。
